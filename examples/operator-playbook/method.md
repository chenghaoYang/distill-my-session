# 这份材料是怎么做出来的

## 来源与范围

- 一台机器上 7 天内的 Claude Code 和 Codex 会话记录。
- 并发统计覆盖 65 个交互 session（每个至少 2 条人类 prompt）。程序化批量运行没有计入，涉及个人生活的 session 整个排除。
- 精读 6 个 session，按工作类型挑选：研究项目的团队推进、训练作业看守、模型部署与评测、调研加新算法、Codex 数据流水线、skill 与 benchmark。

## 流程

1. **digest**：脚本把会话记录变成两个视图。一个只有人类 prompt；另一个把每轮的最终回复插回去，普通工具调用压成一行计数，编排类调用（派活、消息、cron、提问、compaction）单独保留。这一步同时做第一层消密：密钥、邮箱、主机、路径、项目名、身份信息和一份 denylist。
2. **charter**：先写一页目标、读者、要回答的问题、精读名单和消密规则，再开工。
3. **三遍读法**，由 3 个 reader agent 并行完成，每个 session 一张卡片：
   - 只读人类 prompt，还原操作者的意图线；
   - 插入最终回复，看每一问得到了什么；
   - 从结局往回推，找出关键时序，对每一步做反事实检验：删掉这一步，结局还在不在。
4. **综合**：由一个作者读完全部卡片、全部人类 prompt 的时间线和并发统计。先给招式开放编码，再归类并找出类别之间的关系，最后选出核心类别：人只握目标和裁决。每个论断都带锚点，推断标成「推测」。
5. **消密验证**：脚本扫描公开目录，另派一个只看公开目录的 red-team agent，从局外人的角度找能推断出的敏感信息，修正后再扫一遍。

## 消密

- 保留：招式的顺序和时机、prompt 的形式、leading words、harness 机制、故障和恢复。
- 抽象掉：项目内容、方法、数据集、指标和数值、内部服务和主机、人名和机构、时间（改为小时粒度和相对日）。
- 删除：个人生活、个人网络与账号配置、任何凭据。

## 局限

- **消密的把关**：denylist 由整理者提出；公开前经过 leakcheck 和一个只读公开目录的 red-team 审查（14 条意见已按清单修改），操作者同意公开。
- **样本**：65 个里只精读了 6 个，而且偏向编排较重的 session；只做一两件小事的 session 里，可能有别的工作法。
- **快照**：有一个 session 在取样时还在运行，它的「结局」只是快照。
- **可观察性**：Codex 的 agent 间消息和 compaction summary 在磁盘上加密，只能看到对象和时间。
- **指标口径**：「并发」按 15 分钟无记录切分活跃区间；「自己跑下去的时间」在超过约 4 小时的静默处截断。
- **digest 的已知问题**：卡片写成之后才修复了几处，包括个别 harness 唤醒被当成人类 prompt、重复发送没有合并、忙时插话的轮次被标成「无收尾」。统计数字按修复后的版本重算；卡片里的锚点编号以当时的 digest 为准。
- 标成「推测」的内容，都是从时间巧合或间接证据推出来的。
