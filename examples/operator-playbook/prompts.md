# Prompt 模式

每个模式包括：什么时候用 · 模板（`<>` 是槽位）· 一句脱敏原话 · 它会引发什么。名字和 [lexicon.md](lexicon.md) 一致。

## 操作者写给执行 session

### 1. goal read-back（开场先复述）
- **何时**：新 session，或者隔了一夜回来。
- **模板**：`对齐一下 <项目> 的最新进度，然后你先说这个项目的目的是什么？现在完成到哪一步？`
- **原话**：「你先说我们的目标是什么，现在完成到哪一步了。」[S52·T1]
- **引发**：误解在开工前暴露；紧接着就是 goal contract [S32·T1→T2]。

### 2. goal contract（目标成文 + 防漂移）
- **何时**：复述错了，或者项目换了方向。
- **模板**：`不对，我们的目的是：<预先写好的目标陈述>。写到 md 里作为唯一权威，然后清理技术债，防止之后偏移目标。subagent 用 <模型>。`
- **引发**：`docs/goal.md` 写成，之后每个派活 prompt 都以「先读 docs/goal.md」开头 [S32·T2]。

### 3. 资源包络 + 阶段排队
- **模板**：`完成之后就参考 <方向>，找到 gap，然后 agent team 完整设计并推进。资源：<A 只能推理、不可换模型>；<B 随便用>；<外部端点：并发 N>。`
- **引发**：lead 等当前阶段结束再开下一阶段；资源规则逐字进入每个执行 prompt [S32·T3][S32·T5]。

### 4. 一句话派活 + 期限
- **模板**：`<结果>。<期限：跑到明天早上 / 至少 48h / 7 小时内跑不完就停>。agent team 完成。`
- **原话**：「持续推进至少到 48h」[S65·T6]
- **引发**：lead 展开成结构化派活；goal hook 或心跳接管 [S65·T6.1]。

### 5. 叫停并重述
- **模板**：`先不管啊。我们对比的是 <A> 和 <B>。我觉得你有点 overthinking 了？`
- **引发**：3 分钟内停掉 6 个子代理，改做正确的对比 [S50·T2]。

### 6. 止损换资源
- **模板**：`算了，<这条路> 不要做了，删除 <中间产物>，只保留 <结果>。` 下一条：`<新资源的访问方式>。都好好利用。agent team 完成。`
- **引发**：5 个候选只测完 2 个 → 25 个测完 24 个 [S28·T24→T26]。

### 7. 只要结果 + 停止条件
- **模板**：`给我看看结果就行。` / `测 <这两个> 就行，测好就不管其他的了。`
- **引发**：lead 不再调用工具，直接出结果表 [S28·T32]；长尾不再追 [S28·T33]。

### 8. 把目标升级进监控
- **模板**：`反正确保 <X> 好。`
- **引发**：cron 首句改成 “Goal: ensure X is GOOD, not just alive.” [S63·T6]

### 9. 运营契约（长时间生产前）
- **模板**：`<扩大范围>。<验收指标和期限>。确保不把我电脑搞爆炸：大文件放远端。把这些都记录到 md 防止忘记。<N>h 一次吧，每次把任务安排好就行。`
- **引发**：约定写成文件；心跳频率改为 N 小时，指令里写明截止和频率 [S61·T5]。

### 10. 技能入库
- **模板**：`把 <这些技能> 放进项目，登记到 AGENTS.md，防止到时候我一个一个要说一次。`
- **引发**：之后每次唤醒都先读技能索引 [S61·T3]。

## 操作者在 session 之间转发

### 11. 让审阅 session 写下一条 prompt
- **审阅方**：`去阅读 <执行 session> 的最新实验。你觉得哪里不够好？仔细思考，可以调研。给出一个 review 和发给它的提示词。` [S21·T10]
- **执行方收到的 prompt 形状**（改写）：`先修正影响结论的问题，不要把「<若干绿灯>」当作 <契约> 已正确。目标保持：<一句目标>。这一轮不要扩 <范围>、不要加 <预算>、不要换 <方向>。` [S15·T16][S22·T13]
- **引发**：执行方先修正结论级的问题，再扩大实验。

### 12. review 回灌
- **模板**：`新的 review：<path>。你觉得这部分的 review 正确吗？需要修改吗？`
- **引发**：lead 逐条对照代码核实后再接受，并撤回说过头的推断 [S32·T4][S32·T7]。

### 13. 会话记录当起始上下文
- **模板**：`参考 <另一个 harness> 的这个会话 <会话信息或日志路径>，完整推进。`
- **引发**：新 session 从别处的轨迹接着做 [S13·T1][S31·T1]。

### 14. 讲给我听（交付前）
- **模板**：`中文讲解一下 <结论>：每个部分是什么意思。`
- **引发**：给出机制、局限和改进提议 [S50·T7][S07·T2]。

## lead 写给 teammate（从轨迹里抽出的骨架）

### 15. 派活骨架
```text
你是 <角色名>。
先完整读 <brief / goal.md / plan 的某几节>，严格遵守。
你负责：<文件或范围>。只创建和修改分给你的文件；需要改别人的文件时，发消息给 lead 转发。
步骤：1) … 2) …（失败时按 <fallback 顺序>）
验收：<smoke 命令> 通过，且 <验收信号>。
汇报：不超过 <N> 行，包含 <字段>。
不要：<commit / 碰参考实现 / 跑评测，那是下一个 agent 的活 / 调用付费服务超过 K 次>。
```
来源：[S28·T1][S32·T3.1][S65·T4][S50·T1]

### 16. 唱反调的成员
- 红队：`找出会让结论无效的阻断缺陷。` [S32·T3.1]
- novelty-checker：“try HARD to show that the proposed … is NOT novel; ‘similar ideas exist’ does not count.” [S65·T2]
- 只读审计：“independent, READ-ONLY code auditor … do not run experiments.” [S65·T6.1]
- fresh eyes：“You are an independent reviewer (fresh eyes).” [S32·T11.4]

### 17. 心跳指令骨架（cron 或 automation）
```text
Goal: ensure <X> is GOOD, not just alive.
已授权：<可以做的动作>，直到 <完成条件>。
先读：<AGENTS.md / 技能索引 / 状态文件>。
执行：<命令、进程号、路径>（需要沙箱外权限的命令，事先由人逐条授权）。
检查：<指标趋势，对照基线>；平台期或报错时 <怎么做>。
条件动作：当 <条件> 时 <停 / 起 / 记账 / 验证>。
不要：<启动训练 / 下载模型 / 换评判模型>。
频率：每 <N> 小时；截止 <D>。每次写状态文件。
```
来源：[S63·T4.1][S63·T6][S63·T6.4][S61·T4.1][S61·T6.1]
